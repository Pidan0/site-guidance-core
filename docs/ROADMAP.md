# 能力状态和补充顺序

## 已在本仓库实现

需求校验与追问、可解释路线、复合需求差距、实施任务、静态站生成、中英文显式译文、资料局部修改、不可变版本与回退、文件完整性、基础质量检查、草稿交接与公开准备包。

证据入口：test/。外部既有插件的测试不计入本核心测试结果。

## 根据首个真实客户补充

| 客户需要 | 应增加的模块 | 完成证据 |
|---|---|---|
| 真实表单线索 | 表单供应商连接、限流、防垃圾、收件与导出 | 成功、失败、重复及未授权路径实测 |
| 客户登录改内容 | CMS、权限、草稿、预览、发布回退 | 多角色编辑与越权测试 |
| 在线交易 | 商品、购物车、支付与订单连接器 | 指定商户条件下付款、失败、重复回调、退款和对账 |
| 票务 | 日期／场次容量、票种、核销与改退连接器 | 购买到入园核销的实际路径 |
| 预约 | 时区、时段容量、改期与取消连接器 | 重叠预约、取消释放、超时与退款 |
| 其他语言 | 界面词典、译文模型、RTL及审核 | 对应语言页面与业务信息一致 |
| 可视化编辑 | 受控组件编辑、资料源和版本差异 | 编辑与再次生成不丢内容 |
| 图片与视频 | 资源导入、尺寸与格式、引用、授权和迁移 | 引用有效、可交接，原件与授权范围可回查 |
| 批量客户 | 多租户隔离、权限、资源与账单 | 客户数据与发布权限隔离测试 |

只有实现、验收证据和文档齐全后，才将对应能力改为implemented。知识目录不自动赋予运行权限；新增外部操作需遵循宿主授权。

## 发布与维护

本轮不规定未经验证的固定开发期限或收益。先用不同类型的真实需求检验判断是否合适，再记录交付、返工、运维和第三方成本。平台与许可变化由SOURCES记录核对日期，不能把旧报价固化成路由硬规则。
