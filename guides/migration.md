# 已有平台优先改进，必要时再迁移

用户确认已有平台能满足目标，且没有与之冲突的自托管／源码要求时，先配置和改进。核对现有插件、主题、数据与账号权限，避免无依据重新建一套。

必须迁移时，先做：

1. 内容、资源、产品、客户及业务记录的可恢复备份；按实际权限和用途处理个人信息。
2. 旧URL清单、新URL映射、重定向、canonical、语言与站点地图计划。
3. 对表单、搜索、登录、支付、订单、CMS等托管功能逐项确认替代路径。能导出HTML不等于业务功能能迁移。
4. 在测试环境核对页面与数据，明确切换时间、业务暂停窗口和回退条件。
5. 切换后按实际地区验证访问和关键行为，保留旧系统直到确认可回退。

完成依据：关键内容和业务记录能对上，目标路径可用，责任方能接手维护；不能只以新页面更好看验收迁移。

结构化版本见 knowledge/playbooks.json（路线existing-platform）；`node bin/site-core.mjs playbook --route <路线id>` 或 `--capability <能力id>` 可输出带步骤、验收用例和交接物的手册。
