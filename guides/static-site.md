# 展示与询盘站执行

适用：核心目标能用信息页面和联系入口完成。已有商城或预约系统也可采用展示站加明确外链，前提是在brief中确认外部承接。

## 动作

1. 确定目标受众、首要行动、语言、页面与维护方。
2. 取得品牌、介绍、产品或服务、联系方式和可使用素材。未提供的价格、资质、销量不能补写。
3. 参考site示例填写每种语言内容，产品／服务用稳定id对应。
4. 图片：用`media add`把png/jpeg/webp/avif原件放进工作区media/（不收SVG，单张不超过5MB），在`site.media`登记每种语言的alt与授权来源、权利人、使用条件，再用`heroImage`或条目`image`引用。授权为用户自报，核心不核实；拿不到授权记录的图片不要用。换图后重新build会得到新版本，回退会恢复旧原件。
5. 询盘表单：brief确认`features.forms=true`后，在`site.form`填写接收服务给出的HTTPS地址和字段（每种语言的label，至少一个email或tel）。核心只渲染表单并限制CSP提交目标，送达由所选服务负责，见integrations。
6. init、build，检查本地结果和GUIDANCE。用户或设计执行者在目标设备检查实际可读性。
7. 通过update改资料，再build。旧版本保留；发现手改站点时先保留和核对修改，不能覆盖。
8. 试走联系入口，记录哪一种路径已经验证。邮件客户端能打开不等于邮件已送达；有表单时做一次真实提交并确认收件，再记录review form。
9. 按publishing准备公开包和交接。完整示例见`examples/b2b-full.*`。

## 交付与验收

网站文件、内容源（含图片原件）、当前版本、检查结果和维护说明齐全。表单页面存在不等于线索送达，需真实提交证据；外链购票或购买只证明入口存在，订单与收入需要外部系统回传证据。
